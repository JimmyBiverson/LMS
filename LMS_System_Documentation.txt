1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
EduLab is a modern, enterprise-grade Learning Management System (LMS) designed to democratize high-quality online education and training. Grounded in a highly modular and secure Model-View-Controller (MVC) architecture, the platform bridges the gap between students, educators, corporate organizations, and system administrators.

The primary purpose of EduLab is to provide educational institutions, corporate departments, and individual instructors with a robust platform to create, manage, deliver, and track interactive courses. Unlike traditional platforms that offer a one-size-fits-all approach, EduLab implements an advanced role-based routing model that partitions user interactions into specialized dashboards tailored to each stakeholder's workflows.

Key Objectives:
* Academic Excellence: Provide an intuitive layout for students to engage with video lessons, document materials, quizzes, and assignments.
* Operational Efficiency for Instructors: Empower educators to create courses, upload lecture media, design automated quizzes, manage grade books, and communicate with students.
* Multi-Tenant Organization Support: Allow businesses and schools to register as Organization entities to enroll, monitor, and audit their teams' training progress.
* Comprehensive Administrative Control: Provide administrators with tools to moderate content, audit transactions, track system-wide activities, and manage platform configurations.

--------------------------------------------------------------------------------
2. SYSTEM OVERVIEW & ARCHITECTURE
--------------------------------------------------------------------------------
EduLab is built on top of Laravel 13.8 following strict MVC paradigms. The frontend utilizes Tailwind CSS v4, Alpine.js, and Remixicon icons to deliver a fast-loading and visually premium interface. The application logic is segmented into a presentation layer (Blade templates), a routing/middleware layer, and a service layer that handles complex domain operations to keep controllers maintainable.

Core Operational Workflow:
* Routing & Middleware Grouping: HTTP requests hit role-based middleware to determine permissions.
* Controller Dispatching: Controllers validate the request payload and call the required domain service.
* Service Logic Execution: The service layer performs calculations, writes database updates, triggers events, and fires system notifications.

--------------------------------------------------------------------------------
3. USER ROLES & ACCESS CONTROL
--------------------------------------------------------------------------------
EduLab implements a Role-Based Access Control (RBAC) model. 

* Student: 
  Students are the primary consumers. They register, log in, browse the catalog, purchase/enroll in courses, view lessons, complete timed quizzes, submit assignments, track their progress percentage dynamically, and download PDF certificates.

* Instructor:
  Instructors are content creators. They manage courses, structure curriculum sections, upload video lectures and resources, create quizzes with passing marks, manage assignment deadlines, grade submissions, and review course analytics.

* Organization:
  Organizations represent corporate clients. They invite or register team members, assign them to training pathways, customize portal branding, and audit cohort progress via detailed statistical reporting.

* Administrator:
  Administrators have full administrative authority over the entire platform. They moderate users, approve or suspend courses, review flagged content, resolve support tickets, configure homepage carousels (sliders), manage SEO categories, and monitor granular platform activity logs.

--------------------------------------------------------------------------------
4. MULTI-TENANT AUTHENTICATION SYSTEM
--------------------------------------------------------------------------------
Authentication is unified under secure login and register endpoints, utilizing distinct tabs to collect specific data for role-specific flows.

* Registration Flow: Validation depends on the user's role. Instructors require designations, organizations require structural details. Passwords are encrypted using BCrypt.
* Login & Redirection Flow: Once authenticated, the system uses a dynamic helper method to redirect users to their specific dashboard (/dashboard for students, /instructor for instructors, /org for organizations, and /admin for administrators).
* Session & Access Control Middleware: Every dashboard route is protected by Laravel's auth middleware and custom role-verification middleware to prevent horizontal privilege escalation.

--------------------------------------------------------------------------------
5. COURSE MANAGEMENT LIFECYCLE
--------------------------------------------------------------------------------
Instructors and Administrators manage courses through structured pipelines.

* Course Lifecycle States: Courses move from Draft (hidden), to Pending (awaiting admin review), and finally to Active (published and purchasable).
* Asset Processing: Thumbnails are validated and compressed. Preview videos (used for the interactive hover effect) are safely stored. Lesson media supports videos and documents.
* Enrollment System: Integrating seamless logic to separate public viewers from enrolled students.

--------------------------------------------------------------------------------
6. INTERACTIVE LEARNING EXPERIENCE WORKFLOW
--------------------------------------------------------------------------------
* Catalog Discovery: Search and filter courses easily.
* Interactive Video Previews: Hovering over a course card triggers a lightweight Alpine.js-powered preview video.
* Enrollment: Users can enroll in free courses with one click or pass through a secure payment gateway for paid courses.
* Lesson Consumption: The lesson viewer features a collapsible curriculum sidebar, video player, and attached resource downloads.
* Progress Synchronization & Resume Learning: Video playhead timestamps and completed lesson states are saved dynamically in the database.

--------------------------------------------------------------------------------
7. ASSESSMENT ENGINE: QUIZZES & ASSIGNMENTS
--------------------------------------------------------------------------------
* Quiz Timers & Auto-Submission: Quizzes have strict time limits tracked via frontend counters and backend timestamps. They auto-submit when time expires.
* Auto-Grading: QuizEnhancementService instantly evaluates responses against correct answers, generating percentage scores and determining pass/fail status.
* Assignment Deadlines: Instructors set due dates. The system detects late submissions and can apply automated penalty deductions.
* Manual Grading: Instructors review uploaded files and provide manual numeric scores and written feedback.

--------------------------------------------------------------------------------
8. DATABASE-DRIVEN PROGRESS TRACKING SYSTEM
--------------------------------------------------------------------------------
Progress tracking keeps students accountable and informs analytics.
* Lesson Completion: Toggling a lesson as complete updates the lesson_completions table.
* Percentage Calculation: Progress is calculated dynamically: (Completed Lessons / Total Lessons) * 100.
* Resume Learning: The system queries the lesson_completions table to find the last accessed lesson and last watched video position to return students exactly where they left off.

--------------------------------------------------------------------------------
9. ADMINISTRATIVE MANAGEMENT PANEL
--------------------------------------------------------------------------------
* User & Course Oversight: Complete visibility into user lists and course approval queues.
* Activity Logging: Every administrative action (deleting users, changing settings) is strictly logged with IP, User Agent, and timestamp for absolute security auditing.
* Dynamic CMS: Admins configure the homepage Hero Sections, interactive Sliders (including setting transition durations), Testimonials, and Noticeboards.

--------------------------------------------------------------------------------
10. FRONTEND ARCHITECTURE & UI/UX FEATURES
--------------------------------------------------------------------------------
* Design System: Custom-built utilizing Tailwind CSS v4, providing vibrant gradients, glassmorphism elements, and rounded geometries.
* Interactive Elements: Muted HTML5 hover video previews for courses, animated tab switchers, and fluid collapsible sidebars.
* Mobile Responsiveness: All layouts degrade gracefully to mobile screens with sliding drawers and touch-optimized navigation menus.

--------------------------------------------------------------------------------
11. DETAILED DATABASE & BACKEND STRUCTURE
--------------------------------------------------------------------------------
* users: Stores core identity, role enum, and hashed credentials.
* courses: Stores titles, slugs, pricing, thumbnails, and lifecycle status.
* lessons: Stores curriculum sections, video files, and free-preview boolean flags.
* enrollments: Pivot table mapping users to the courses they purchased.
* lesson_completions: Tracks completion timestamps and video playhead positions.
* quizzes & quiz_results: Stores questions, correct answers, timers, and attempt logs (with composite unique indexes to prevent double submissions).
* activity_logs: Secure append-only table for administrative audit trails.

--------------------------------------------------------------------------------
12. CORE TECHNOLOGIES USED
--------------------------------------------------------------------------------
* Backend: PHP 8.3+, Laravel 13.8 (Eloquent ORM, Middleware routing).
* Frontend: Tailwind CSS v4, Alpine.js 3, Remixicon, Vite 8 build system.
* Database: SQLite (Development/Testing) / MySQL (Production).
* PDF Generation: barryvdh/laravel-dompdf for verifiable certificates.

--------------------------------------------------------------------------------
13. COMPREHENSIVE SECURITY BLUEPRINT
--------------------------------------------------------------------------------
* Authentication: BCrypt password hashing.
* Authorization: Strict Role-Based Middleware.
* Exploit Prevention: Global CSRF token verification for all state-mutating requests, PDO parameter binding to stop SQL Injection, and Blade's automatic HTML escaping to prevent XSS.
* Access Control: Unique index constraints prevent duplicate enrollments and quiz submissions.

--------------------------------------------------------------------------------
14. CHALLENGES & SOLUTIONS
--------------------------------------------------------------------------------
* Dashboard Redirection Bug: Initially, all users were redirected to the student dashboard. Solution: Implemented a robust redirectToDashboard() helper that intelligently parses the user's role and routes them accordingly.
* Hover Preview Video Failures: The course cards were not loading videos on the public catalog. Solution: Passed the full Eloquent Course model into the blade component instead of isolated strings, allowing dynamic resolution of free-preview lessons and video URLs.
* 500 Server Errors on Profiles: Accessing public profiles crashed due to accessing relation strings as objects. Solution: Safely implemented null coalescing operators and called relation methods correctly in the Blade templates.
