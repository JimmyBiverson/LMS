Other Common Uses of .htaccess
Beyond Laravel, .htaccess is used for:

1. Security (Blocking Access)
apache
# Block everyone from viewing .env file
<Files .env>
    Order allow,deny
    Deny from all
</Files>

# Block IP addresses
Deny from 192.168.1.100
Allow from all
2. Custom Error Pages
apache
ErrorDocument 404 /errors/404.html
ErrorDocument 403 /errors/403.html
ErrorDocument 500 /errors/500.html
3. Force HTTPS (SSL)
apache
RewriteCond %{HTTPS} off
RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
4. Redirect Old URLs to New Ones
apache
Redirect 301 /old-page.html /new-page
Redirect 301 /contact-us https://myngosite.com/contact
5. Cache Control
apache
<FilesMatch "\.(css|js|jpg|png)$">
    Header set Cache-Control "max-age=31536000, public"
</FilesMatch>
6. Prevent Directory Listing
apache
Options -Indexes
Stops people from seeing your folder contents if there's no index file

Why .htaccess Is Perfect for Shared Hosting
Without .htaccess:
You need access to Apache's main configuration file (httpd.conf or .conf files).

Requires root access (not available on shared hosting)

Changes affect entire server (risky for other users)

Requires restarting Apache (causes downtime)

With .htaccess:
You can configure everything from the folder itself.

✅ No root access needed (works on cPanel/shared hosting)

✅ Changes are instant (no server restart needed)

✅ Only affects that directory (safe for multi-user environments)

.htaccess vs web.config
.htaccess	web.config
Apache servers only	IIS (Windows) servers
Directory-based configuration	XML-based configuration
More common in Linux hosting	Used in Windows hosting
Laravel uses this by default	Laravel provides a version for IIS
Common .htaccess Errors and Fixes
Error: 500 Internal Server Error
Cause: Syntax error in .htaccess
Fix: Check your syntax, especially missing spaces or brackets

Error: Rewrite rules not working
Cause: mod_rewrite not enabled
Fix: In cPanel, check "Apache Modules" or contact your host

Error: 404 for all pages except homepage
Cause: Rewrite rules not configured correctly
Fix: Ensure the .htaccess file is in the public/ folder, not the project root

TL;DR
.htaccess is a configuration file that:

Serves as the "traffic controller" for your website

Enables clean URLs (no index.php?page=about)

Routes all requests to Laravel's entry point (index.php)

Handles security, redirects, and caching

Works without needing access to server configuration (perfect for cPanel)

Without it: Laravel works, but URLs look ugly and break easily
With it: Clean, professional URLs and proper request handling
